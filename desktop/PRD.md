# js-pet 产品需求文档（PRD）

> 版本：v1.0　｜　日期：2026-10-04　｜　状态：待确认后冻结
> 本文档是 js-pet 第一版开发的**唯一依据**。第 8 章「必须完成」与第 9 章「暂时不做」共同构成范围边界，任何超出边界的需求一律进入 v2 待办。

## 1. 产品目标与使用场景

### 1.1 一句话定义

> 一个装在自己电脑上的桌面陪伴型宠物：平时安静待在桌面角落，会呼吸、眨眼、随机表演小动作；你可以喂它、摸它、陪它玩，它会慢慢积累心情与亲密度、随等级长大；你可以上传自己的图把它换成任何形象——**关掉再打开，它还在原地，还是个"记得你"的它。**

### 1.2 产品目标

| # | 目标 | 说明 |
|---|---|---|
| G1 | 真正"活在桌面上" | 透明、置顶、不占任务栏，不打断用户，随时可见 |
| G2 | 有陪伴感而非一次性玩具 | 轻度养成，互动可积累，**关闭/重启数据不丢** |
| G3 | 形象可自定义 | 内置原创形象 + 用户上传图片自动生成三视图 |
| G4 | 公开免费、零门槛 | 任何人下载即装即用，**无需注册、无需联网** |

### 1.3 目标用户

- **主要**：喜欢桌宠/桌面挂件的普通用户（学生、办公族），以 Windows 为主
- **次要**：macOS 用户
- **共同特征**：想要"开机就有个小东西陪着我"，但**不想被打扰、不想注册、不想数据被收集**

### 1.4 核心使用场景

| # | 场景 | 期望结果 |
|---|---|---|
| S1 | 开机后 | 宠物出现在桌面角落，还是昨天那只 |
| S2 | 工作时 | 安静待在角落，不挡操作、不抢焦点；鼠标划过会看过来 |
| S3 | 休息时 | 点它、摸它，它会开心并说句话 |
| S4 | 想起来时 | 右键喂它、陪它玩，看等级上涨 |
| S5 | 想换形象 | 上传一张自己的图，自动抠图并切三视图，一键换装 |
| S6 | 几天没开 | 再打开时它有点饿、有点蔫（离线结算），喂一下能哄好 |
| S7 | 想让它挪窝 | 拖到任意位置，下次还在那儿；开启漫游看它溜达 |

### 1.5 明确不解决的场景

- 不是效率工具，**不做日程 / 待办 / 提醒**（详见 6.3）
- 不做社交、排行榜、内购

## 2. 整体页面框架与导航结构

桌面宠物没有传统"网页"，它的"页面框架"分三层。

### 2.1 三层框架

| 层 | 名称 | 特征 |
|---|---|---|
| **L1 桌面层** | 宠物本体窗口 | 透明、无边框、置顶、不占任务栏；常驻，无任何 UI 外壳 |
| **L2 面板层** | 主窗口（点开才出现） | 常规窗口，承载「养成 / 形象 / 设置」三个模块 |
| **L3 菜单层** | 托盘菜单 + 右键菜单 | 全局导航入口，是 L2 关闭后唯一的入口 |

### 2.2 导航结构

```
托盘图标 ──左键──▶ 显示 / 隐藏宠物
        └─右键──▶ 完整菜单 ──▶ 养成面板 / 形象管理 / 设置 / 退出
宠物本体 ──右键──▶ 与托盘右键同一套菜单（快捷入口）
主窗口   ──左侧竖向标签──▶ 养成 · 形象 · 设置
```

- **主入口**：托盘图标
- **快捷入口**：在宠物身上右键
- **面板内导航**：左侧竖向标签切换三个模块
- **退出**：只在托盘/右键菜单的「退出」中，避免误关

### 2.3 菜单项（v1 固定清单）

显示/隐藏宠物 · 喂食 · 抚摸 · 玩耍 · 让它睡觉 · 打开形象管理 · 打开设置 · 漫游模式（开关）· 开机自启（开关）· 关于 · 退出

## 3. 首页（宠物本体）的内容结构

首页 = 桌面上的宠物本身。它不是一个"信息页面"，而是一个**活的对象**。

### 3.1 视觉构成

1. **宠物形象**：多视角贴图（正面 / 侧面 / 背面）
2. **待机动画**：呼吸、随机眨眼、视线跟随鼠标
3. **气泡**：说句话或状态提示，出现在宠物上方
4. **状态可视化**：不常驻数值，而是**用状态驱动表情与动作**——饿了蔫、开心蹦、困了打盹
5. **落地软阴影**：随跳跃/动作缩放，强化立体感

### 3.2 首页上的操作

| 操作 | 效果 |
|---|---|
| 单击 | 抚摸，+亲密度（有冷却与每日上限） |
| 双击 | 触发一个随机开心动作 |
| 右键 | 弹出菜单 |
| 拖拽 | 移动位置并记住 |
| 鼠标划过 | 眼珠跟随光标 |

### 3.3 首页**不**显示

- 不显示数值条、不显示等级数字（需点开养成面板才可见）
- 不弹系统通知

## 4. 各模块用途

| 模块 | 层 | 用途 |
|---|---|---|
| **A 桌宠本体** | L1 | 陪伴。承载形象、动画、互动，是全部情感体验的载体 |
| **B 养成面板** | L2-1 | 把"看不见的状态"变可见：展示饱食度/心情/亲密度/等级与成长进度，并提供喂食、抚摸、玩耍的集中入口 |
| **C 形象管理** | L2-2 | 换装。内置原创形象 + 上传自定义图（自动抠图/切三视图/归一化）+ 多套保存切换 + 导入导出形象包 |
| **D 设置** | L2-3 | 控制软件行为。开机自启、宠物大小、漫游模式、数据备份与恢复、关于/版本 |
| **E 托盘与右键菜单** | L3 | 全局导航与快捷操作，所有功能的统一入口 |

## 5. 各模块第一版最必要的数据与操作

### 5.1 模块 A · 桌宠本体

- **读取**：`position{x,y}`、`display{size, monitorId}`、`currentLookId`、`stats{...}`（驱动表情）、台词表
- **写入**：`updatePosition`、`setLook`、`updateStats`

### 5.2 模块 B · 养成面板

**必要数据**

| 字段 | 类型 | 说明 |
|---|---|---|
| `hunger` | number 0–100 | 饱食度 |
| `mood` | number 0–100 | 心情 |
| `bond` | number ≥0 | 亲密度（累计值） |
| `level` | number 1–99 | 等级，由 `bond` 换算 |
| `lastTickAt` | timestamp | 上次结算时间（离线结算基准） |
| `todayInteractions` | `{date, count}` | 每日互动计数，跨天重置 |

**必要操作**：喂食 · 抚摸 · 玩耍 · 查看成长进度
（所有写操作走同一入口 → 统一结算 → 统一保存）

### 5.3 模块 C · 形象管理

- **必要数据**：`looks[] { id, name, source:'builtin'|'custom', assets{front,sideA,sideB,back,wave,sleep}, createdAt }`、`currentLookId`
- **必要操作**：切换形象 · 上传并生成（抠图 + 切三视图 + 归一化）· 删除自定义形象 · 导出/导入形象包

### 5.4 模块 D · 设置

- **必要数据**：`autoStart(bool)`、`size(number)`、`wanderEnabled(bool)`、`monitorId`、`schemaVersion`
- **必要操作**：开关开机自启 · 调整宠物大小 · 开关漫游 · 备份数据 · 恢复数据 · 查看版本

### 5.5 模块 E · 托盘与菜单

- **必要数据**：无（读取 B/D 状态用于显示勾选态）
- **必要操作**：触发上述所有操作

## 6. 首页、今日计划与各模块之间的关系

### 6.1 数据流总览

- **首页（L1）是唯一的数据产生者**：所有互动都发生在宠物身上
- **养成面板（B）是数据解释层**：只读展示 + 提供批量入口，不自己持有状态
- **形象管理（C）/ 设置（D）是配置层**：改变的是"长什么样、怎么跑"
- **主进程是唯一写入者**：任何变化都经 IPC → 统一落盘，渲染进程不直接写文件

### 6.2 关系图

```
配置层 C/D ──▶ 主进程(唯一落盘) ──▶ pet-data.json
                    ▲
首页 L1(产生数据) ───┘
   │
   └──▶ 养成面板 B(只读展示 / 批量入口) ──▶ 主进程
```

### 6.3 关于「今日计划」

**本项目没有"今日计划"模块**——js-pet 不排期、不待办、不提醒。
提纲中该位置在 js-pet 中对应的是养成系统里的**每日机制**：

- 每次互动使 `todayInteractions.count + 1`，达到每日上限后当天不再增加亲密度
- 跨天首次启动时 `todayInteractions` 归零（每日重置）
- 该机制**归属首页（L1）**，不单独开页、不产生独立模块

## 7. 本地数据文件、备份与恢复要求

### 7.1 存放位置

- **Windows**：`%APPDATA%/js-pet/`
- **macOS**：`~/Library/Application Support/js-pet/`

### 7.2 文件清单

| 文件 | 内容 | 可否删除 |
|---|---|---|
| `pet-data.json` | 全部养成数据 + 位置/大小 + `schemaVersion` | 否（删=从头开始） |
| `looks/` | 自定义形象贴图（webp/png） | 可（对应形象消失） |
| `backups/pet-data-YYYYMMDD-HHmmss.json` | 自动备份 | 可 |

### 7.3 写入要求（硬性）

- **原子写**：先写 `.tmp` 再 rename 替换，任何时刻断电都不会得到半截文件
- **节流**：位置类高频变化合并写入（如 2 秒内只写一次）
- **关键时点立即写**：互动后、退出前、切换形象后
- **抗损坏**：启动时主文件解析失败 → 自动回退最近一次备份并提示用户

### 7.4 自动备份

- 每次成功启动后，若距上次备份 > 24h，写一份带时间戳的备份
- 最多保留最近 **5** 份，超出自动删除最旧

### 7.5 手动备份 / 恢复

- 设置 →「备份数据」：导出单个 `.json`（含养成数据；可选是否含自定义形象）
- 设置 →「恢复数据」：选择 `.json` → 校验 `schemaVersion` → 覆盖并重启宠物
- 版本不兼容时给出**明确提示**，不静默失败

### 7.6 卸载行为

- 卸载默认**保留**用户数据目录，并在卸载向导中说明该目录位置

## 10. 可以实际检查的验收标准

### A. 形态与窗口
- **A1** 双击桌面图标即可运行，无需命令行、无需预装 Node
- **A2** 宠物背景完全透明，边缘无白底 / 黑框残留
- **A3** 任务栏中**不出现**宠物窗口；切到其他窗口时宠物仍在最上层
- **A4** 除宠物本体范围外，鼠标点击**穿透到桌面**（可点到桌面图标）
- **A5** 宠物本体范围内的点击不会穿透（能选中宠物）

### B. 数据持久化（核心验收）
- **B1** 拖动宠物到新位置 → 关闭软件 → 重开 → 位置不变
- **B2** 喂食使饱食度上升 → 关闭 → 重开 → 数值保留
- **B3** 强杀进程（任务管理器结束）→ 重开 → 数据未损坏、未回退到初始值
- **B4** 手工把 `pet-data.json` 改成非法内容 → 启动不崩溃，回退备份并提示
- **B5** `%APPDATA%/js-pet/` 下确实生成了数据文件与 `backups` 目录

### C. 养成逻辑
- **C1** 把系统时间前进 6 小时 → 重开 → 饱食度/心情按衰减规则下降（离线结算生效）
- **C2** 抚摸达到当日上限后，亲密度不再增长，界面给出提示
- **C3** 跨天后重开，每日互动计数归零
- **C4** 亲密度跨过阈值时等级 +1，并播放升级动作
- **C5** 饱食度 < 20 时宠物呈现"饿"的表现（动作/台词与常态不同）

### D. 形象系统
- **D1** 内置原创形象正常显示，三视图转身连贯、大小一致
- **D2** 上传一张白底宠物图 → 自动抠掉背景、切成视图、切换后比例正常
- **D3** 导出形象包后在另一份安装上导入，形象可复现
- **D4** 删除自定义形象后，缩略图与磁盘文件同步消失

### E. 菜单与设置
- **E1** 托盘图标存在，左键切换显示/隐藏，右键菜单完整
- **E2** 开启「开机自启」→ 重启系统后宠物自动出现；关闭后不再自动出现
- **E3** 漫游开关开启后宠物在可见区域内移动，关闭后回到静止
- **E4** 「退出」能真正结束进程（任务管理器中无残留）

### F. 备份与恢复
- **F1** 恢复一份旧备份后，数值回到备份时刻的状态
- **F2** `schemaVersion` 不兼容的备份文件被拒绝，并有明确提示

### G. 打包与分发
- **G1** Windows：安装包安装后开始菜单/桌面有快捷方式，可正常卸载
- **G2** Windows：绿色版解压后双击即用，不写注册表
- **G3** macOS：`.dmg` 拖入应用目录后可运行（首次需右键打开，指引文档存在）

### H. 安全与隐私
- **H1** 断网状态下全部功能可用（无任何网络请求）
- **H2** 渲染进程中无法访问 Node / 文件系统（DevTools 里 `require` 不可用）
- **H3** 数据目录内不含任何用户隐私数据（无系统信息采集）

## 附录 B · 技术架构摘要

```
主进程 main process      窗口 / 托盘 / 开机自启 / 数据读写
        ↕ IPC
preload 桥               contextBridge 白名单 API
        ↕ IPC
渲染进程 renderer        宠物渲染 / 动画 / 养成面板
        ↑
原创形象素材             正 / 侧 / 背 / 招手 / 打盹
```

- **渲染/动画/形象处理逻辑**尽量原样复用现有 `pet-demo-v3.html`，仅把 `localStorage` 替换为 preload API
- **安全基线**：`contextIsolation: true`、`nodeIntegration: false`，渲染进程不直接碰 Node
- **数据层**按仓储层（Repository）抽象：本地适配器先行，云适配器留空位
- **鼠标穿透**：`setIgnoreMouseEvents(true, { forward: true })`，在宠物本体区域动态关闭穿透
