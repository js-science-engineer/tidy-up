## 1. 产品目标与使用场景

### 1.1 一句话定位
一个跑在自己电脑上的实验室收纳管理工具：**拍一张照片 → 云端 AI 认出是什么 → 建议放哪个柜子哪一格 → 一键入库 → 随时搜索、随时可视化查看每个柜子里有什么**。

### 1.2 产品目标
1. **降低整理门槛**：不用自己想"这东西算什么类、该放哪"，系统给归类和位置建议
2. **解决"找不到"**：模糊描述也能搜到（如"那个蓝色的测电压的东西"）
3. **数据可追溯**：什么时候入的、放在哪、还剩几个，随时可查
4. **为上线打基础**：代码分层预留，未来可低成本迁移为网站 / App

### 1.3 使用场景
- 实验室物品（开发板、元器件、仪器、工具、耗材等）的**归位与登记**
- 拍照后由 AI 识别 + 联网匹配标准名称与实物图
- 需要找某件物品时**搜索定位**（精确 / 模糊描述）
- 取用物品后**出库扣减**，保持账实一致
- 单人使用（不需要登录、不需要多用户）

## 2. 已确认的关键决策（开发基线，不得擅自更改）

| # | 决策项 | 结论 |

## 4. 首页（总览）内容结构

首页自上而下依次为：

| 区块 | 内容 | 点击行为 |
|---|---|---|
| ① 欢迎语 + 摘要 | 问候语 + 一句话动态（"今天已入库 N 件"） | — |
| ② 统计卡 ×4 | 物品总数 / 区域数 / 柜子数 / 今日入库数 | 跳转对应模块 |
| ③ 空间总览 | 每个区域一张卡：区域名 + 各柜子缩略图（格位色块表示占用：实色=满、半透明=部分、描边=空） | 点击柜子 → 进入收纳空间并定位该柜 |
| ④ **今日计划** | 今日待确认队列（识别后未入库）+ 今日入库记录 + 今日取出记录 | 点击条目 → 跳转识别入库完成确认 / 跳转物品详情 |
| ⑤ 最近入库 | 最近入库的物品卡（缩略图 + 名称 + 位置路径） | 点击 → 物品详情卡 |

> **今日计划不是独立页面**，它是首页的"今日聚合区"：数据来自各模块写入的流水与队列，作用是告诉用户"今天还有什么没办完"。

## 5. 各模块：用途 / 第一版最小数据 / 第一版操作

### 5.1 收纳空间（柜体生成与编辑）
- **用途**：把现实中的柜子数字化为 2D 结构，作为物品位置的载体
- **第一版最小数据**：区域（名称、排序）；柜子（名称、所属区域、所属层、门型：双开/单开/抽屉、层内顺序）；层/抽屉（名称、所属柜、顺序）；箱子（名称、所属层/抽屉、颜色标记）；每个容器自动统计占用率
- **第一版操作**：
  1. **AI 对话生成**：文本描述（如"两层，第一层5个柜子：1个双开门+4个单开门，第二层3个双开门"）→ 生成结构并自动编号（区域一/区域二…），生成前可预览、可重新描述
  2. **拖拽/表单编辑**：添加/删除/重命名区域、柜子、层、抽屉、箱子；调整门型
  3. 2D 可视化浏览：逐级下钻（区域→柜→层→箱），柜内显示箱子标签与占用率条
  4. 撤销最近一次编辑（至少一步）

### 5.2 识别入库
- **用途**：拍照 → AI 识别 → 智能分区建议 → 确认入库
- **第一版最小数据**：物品（名称、别名、类别、图片、估算尺寸档位、创建时间）；存放关系（物品↔位置↔数量）；识别原始结果（置信度、候选名称）；待确认队列状态
- **第一版操作**：
  1. 上传图片（电脑选图/拖拽；手机浏览器上传）
  2. 模式切换：一图一物 / 整层批量（多物框选、逐个确认，可删除误识别项）
  3. 识别结果编辑：名称（可从候选中选）、类别（预设类中选）、数量（步进器）
  4. 联网匹配实物名称与图片：展示候选，用户点选；**跳过则自动选贴合度最高的**
  5. 智能分区建议：给出"区域›柜›层›箱"推荐路径 + 一句理由；可改选任意位置
  6. 确认入库 → 写库存 + 写流水 + 柜体视图即时更新
  7. 识别失败 / 断网 / 无 Key：给出明确错误提示，可重试，不崩溃、不产生脏数据

### 5.3 出库（取出）
- **用途**：取用物品后扣减库存，保持账实一致
- **第一版最小数据**：流水（时间、物品、动作=出库、数量、剩余量）
- **第一版操作**：搜索或浏览定位物品 → 选"取出" → 填数量（全部/部分）→ 确认 → 扣减；**扣到 0 标记"已取空"**（保留位置与记录，不删除物品）

### 5.4 搜索
- **用途**：快速定位物品
- **第一版最小数据**：搜索索引（名称、别名、类别、位置、标签字段）；语义搜索调用大模型的结果（候选物品 + 匹配度）
- **第一版操作**：
  1. 精确匹配：按名称/别名关键词过滤
  2. 语义搜索：模糊描述 → AI 推测可能物品，按匹配度排序展示
  3. 筛选：按类别、区域
  4. 结果行展示：缩略图 + 名称 + 位置路径 + 数量 + 匹配度；点击打开详情

### 5.5 设置
- **用途**：系统配置与数据安全
- **第一版最小数据**：配置文件（API Key、供应商选择、服务端口、主题偏好）
- **第一版操作**：填写/切换 AI 供应商与 Key；切换深浅主题；**一键备份**；**从备份恢复**

### 5.6 统计（占位）
- 第一版仅保留导航入口，点击显示"即将上线"占位页

## 6. 首页 · 今日计划 · 各模块之间的关系

```
                 ┌──────────── 首页（总览）────────────┐
                 │  统计卡 ← 实时聚合各模块数据          │
                 │  空间总览 ← 收纳空间的区域/柜数据      │
                 │  今日计划 ← 汇总"今天的动态与待办"     │
                 └───────┬──────────────┬─────────────┘
                         │ 点击跳转       │ 数据来源
        ┌────────────────┼──────────────┼────────────────┐
        ▼                ▼              ▼                ▼
   收纳空间          识别入库         出库             搜索
   （结构变更）   （待确认队列→入库）  （扣减流水）      （只读查询）
        │                │              │                │
        └────────────────┴──────┬───────┴────────────────┘
                                ▼
                     统一数据层（SQLite + 图片文件夹）
                     所有模块读写同一份数据，首页实时反映
```

关系要点：
1. **今日计划 = 首页的今日聚合区**，不单独成页；数据来源 = 识别入库的"待确认队列" + 当天的入库/出库流水
2. 任何模块确认一个操作（入库/出库/改结构），首页统计卡、空间总览、今日计划**立即更新**（刷新或局部刷新均可）
3. 首页所有区块都可点击跳转到对应模块的对应位置（深链）
4. 搜索为只读查询，不产生数据；数据变更只发生在收纳空间 / 识别入库 / 出库三个模块

## 7. 数据模型（第一版）

### 7.1 层级结构
```
区域 Zone → 柜子 Cabinet → 层/抽屉 Shelf → 箱子 Box → 物品 Item
```
（物品通过"存放关系"挂在任意层级的容器上）

### 7.2 核心实体与字段（最小集）
| 实体 | 字段 |
|---|---|
| Zone | id、名称（区域一…）、排序、创建时间 |
| Cabinet | id、名称、门型(双开/单开/抽屉)、所属区域、所属楼层、顺序 |
| Shelf | id、名称、类型(层板/抽屉)、所属柜、顺序 |
| Box | id、名称、颜色标记、所属 Shelf、顺序 |
| Item | id、名称、别名[]、类别、图片文件名[]、尺寸档位(小/中/大)、创建时间 |
| **Placement** | id、物品 id、容器 id（层或箱）、**数量**、更新时间（同一物品可多条 = 多位置独立数量） |
| Log | id、时间、物品 id、动作(入库/出库/移位/编辑)、数量、位置快照、备注 |
| Category | id、名称、是否预设 |

### 7.3 预设分类（用户确认不调整）
> 电子元件 · 开发板/模块 · 仪器设备 · 线材/连接件 · 工具 · 化学试剂 · 耗材 · 结构件/五金 · 包装/收纳 · 文档/资料 · 其他

## 8. 本地数据文件、备份与恢复

### 8.1 数据目录结构（约定）
```
tidy-up/
├── data/
│   ├── tidy.db          # SQLite 主库（结构、物品、库存、流水、配置外的全部业务数据）
│   ├── images/          # 物品图片（按 物品id/ 建子文件夹，原图 + 缩略图）
│   └── config.json      # API Key、供应商、端口、主题偏好（不入库、不随备份外发 Key 时可选项）
├── backups/             # 自动/手动备份输出目录
└── start（双击启动脚本，启动后自动打开浏览器）
```

### 8.2 持久化要求
1. 所有写操作（入库/出库/编辑结构）**实时落盘**（SQLite 事务提交），刷新、关闭浏览器、重启电脑均不丢失
2. 图片上传后立即写入 `data/images/`，数据库只存相对路径
3. API Key 存后端配置文件，**永不下发到前端**（界面中打码显示）

### 8.3 备份要求
- **手动一键备份**：设置页点击 → 打包 `tidy.db + images/ + config.json(可选含Key)` 为 `backup-YYYYMMDD-HHmmss.zip` 存入 `backups/`
- 每次启动时若当天尚无备份，**自动静默备份一次**（保留最近 10 份，超出自动清理最旧）

### 8.4 恢复要求
- 设置页选择备份 zip → 二次确认 → 覆盖恢复（恢复前自动先做一次当前数据的应急备份）→ 恢复完成提示并刷新界面
- 恢复必须完整还原图库与数据库的一致性（数据库中引用的图片缺失时在设置页提示清单）

## 11. 验收标准（可实际检查）

**A. 启动与持久化**
1. A1：双击启动脚本后 10 秒内浏览器自动打开系统首页
2. A2：入库 3 件物品 → 关闭浏览器 → 重启电脑 → 再次启动 → 3 件物品、数量、图片、位置**全部原样存在**
3. A3：刷新页面（F5）任意时刻，界面数据不丢失、不重置

**B. 收纳空间**
4. B1：在 AI 对话框输入"两层。第一层 5 个柜子：1 个双开门 + 4 个单开门。第二层 3 个柜子，都是双开门。"→ 生成 2 层 8 柜结构，自动编号正确，门型正确
5. B2：能完成一次"新增柜子 → 重命名 → 删除"且视图即时更新
6. B3：能在一个柜子里新建箱子并命名，柜子占用率条随之变化
7. B4：点击首页空间总览的某个柜子 → 跳转到收纳空间并高亮定位到该柜

**C. 识别入库**
8. C1：上传一张 STM32 开发板照片 → 10 秒内返回：名称、类别（落在预设分类内）、置信度、候选名称 ≥2 个
9. C2：联网匹配展示候选实物图；不点选直接确认 → 系统自动采用贴合度最高的一组
10. C3：分区建议给出完整路径（区域›柜›层›箱）和一句理由；改选其他位置后入库，物品出现在**改选后**的位置
11. C4：批量模式上传一张含多物品的照片 → 返回多个识别项，可逐个确认/删除；确认后各自入库
12. C5：同一物品分别入库到两个不同位置 → 两个位置各自显示独立数量，搜索结果总数量 = 两者之和
13. C6：拔掉网线（或填错 Key）再识别 → 出现明确错误提示，界面不崩溃，恢复网络后重试成功
14. C7：手机与电脑连同一 WiFi，手机浏览器打开提示的地址 → 能拍照/选图上传并完成一次入库

**D. 出库与流水**
15. D1：对数量为 3 的物品执行"取出 1" → 该位置数量变 2；取出全部 → 标记"已取空"且物品与历史记录仍可查

## 12. 已确认的关键决策（开发基线，不得擅自更改）

| # | 决策项 | 结论 |

| 1 | 网站部署方式 | **WorkBuddy 云服务托管**：云数据库替代 SQLite、云文件存储替代本地上传目录；不购买自有服务器、免运维 |
| 2 | 用户体系 | **完整多用户注册登录**：邮箱 + 密码注册（后续可扩展手机验证码/微信登录），账号间数据完全隔离 |

## 13. 路径 A：网站上线（云服务托管）

### 13.1 后端云化改造
1. 数据层抽象：`server/db.js` 增加 `local / cloud` 双模式适配层，API 路由与数据结构保持不变；本地开发仍可跑 SQLite
2. 结构化数据：SQLite → 云数据库（云服务托管方案）
3. 图片上传：multer 本地目录 → 云文件存储，数据库存云端引用；接口返回图片 URL
4. AI 大模型调用：改用托管平台免密钥 LLM 调用（或继续由服务端保管 Key，永不下发前端）

### 13.2 多用户体系
1. 注册：邮箱 + 密码；登录：邮箱 + 密码，签发会话 token
2. 全部业务表（zones/cabinets/shelves/boxes/items/placements/logs/categories 等）增加用户归属字段，所有 API 按会话鉴权过滤
3. 账号间数据完全隔离：任意账号无法读取/修改他人数据
4. 前端：新增注册页、登录页；未登录访问跳转登录页；token 会话保持，登出即失效
5. 设置页中的 API Key 管理、备份/恢复等本地特有功能在云端版本的呈现方式随实现调整（云端数据安全由托管平台负责）

### 13.3 电子宠物（PetWidget）适配
1. `tidy-pet-look` 等 localStorage 键按用户隔离（换账号不串自定义形象）
2. 宠物自定义形象上传改走云文件存储
3. 宠物行为、12 态交互、拖拽/复制等功能**保持不变**（含 copyPet 视口钳制修复）

### 13.4 上线与验收
- 部署到托管平台，验证公网访问与 HTTPS
- 本地 `start.bat`、本地服务模式保留可用
